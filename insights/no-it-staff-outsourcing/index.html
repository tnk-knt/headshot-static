01 — PROBLEM

IT担当者がいないことより「誰も管理していない」状態が問題

中小企業では、専任の情報システム担当者を置けず、総務や経理などがIT業務を兼任しているケースがあります。 NTT東日本も2026年5月公開の記事で、専任情シスを置くことが難しい中小企業では、兼任担当者の負担や、トラブル時の相談先がわからないことが課題になりやすいと説明しています。

また、中小企業基盤整備機構は2026年5月の特集で、情報システム担当者がいない企業だけでなく、担当者が他業務と兼務して実質一人で対応する「ひとり情シス」の負荷にも触れています。 重要なのは、担当者の人数そのものより、システム、アカウント、契約、障害対応などを誰が把握し、誰が判断するかが決まっていることです。

この記事の結論

「全部を外注する」「専任者を一人採用する」の二択ではありません。社内に責任者を置き、会社として決めることは社内に残しながら、専門性や継続対応が必要な実務を外部で補完する方法があります。

02 — RISKS

IT担当者不在で起こりやすい6つの問題

1. アカウント・権限管理が曖昧

誰が管理者なのか、退職者のアカウントが残っていないか、重要サービスの権限が誰に集中しているかが分からなくなります。

2. バックアップと復旧手順が不明

バックアップを取っているつもりでも、対象、保存先、復旧方法を確認していなければ、障害時に戻せるとは限りません。

3. セキュリティ更新が後回し

OS、ソフトウェア、ネットワーク機器、クラウドサービスの設定など、日常業務に追われると対応が後回しになりやすい領域です。

4. 障害時の初動が決まっていない

「まずどこへ連絡するか」が決まっていないと、原因切り分けやベンダーへの問い合わせ開始までに時間がかかります。

5. 契約・構成情報が散在する

ドメイン、クラウド、回線、SaaS、保守会社などの契約と管理情報が個人のメールや記憶に分散しやすくなります。

6. 改善の優先順位を決められない

現場から複数の改善要望が出ても、費用対効果やリスクを比較する役割がなければ、場当たり的な導入が増えます。

IPAが2025年に公表した「2024年度 中小企業における情報セキュリティ対策に関する実態調査」では、全国4,191社を調査し、速報版で約7割の企業が組織的なセキュリティ体制を整備していないと報告しています。 IT担当者不在の問題をセキュリティだけに限定することはできませんが、「担当と体制を明確にする」重要性を示す材料の一つです。

参照（2026年8月20日確認）：NTT東日本「情シスアウトソーシングでは何を依頼できる？」、中小企業基盤整備機構「ひとり情シス問題」、IPA「2024年度 中小企業における情報セキュリティ対策に関する実態調査」

03 — OPTIONS

専任採用・兼任・外注の3つの選択肢

専任のIT担当者を採用する

日常的な問い合わせや運用業務が多く、社内に技術知識を継続的に蓄積したい場合は有力です。ただし、インフラ、セキュリティ、業務システム、SaaS、ベンダー管理など、IT業務は幅が広く、一人ですべての専門領域を担当できるとは限りません。

社内の兼任責任者＋外部支援

業務や会社の事情を理解する社員がITの社内責任者となり、技術的な調査、ベンダー調整、運用作業などを外部に補ってもらう形です。 中小企業では、専任採用までの中間策として始めやすい方法です。

情シス業務を外注する

ヘルプデスク、アカウント運用、保守など、役割や手順を定義しやすい業務を外部へ委託します。すべてを外注する必要はなく、負荷やリスクが大きい領域から部分的に始めることもできます。

04 — OUTSOURCE

外注しやすい情シス業務

PC・SaaSの問い合わせ対応

日常的な操作や設定、トラブルの一次切り分けなど、担当者の時間を奪いやすい定型業務です。

アカウント・権限管理の支援

入退社時の作成・停止、権限変更、管理者アカウントの棚卸しなどを手順化します。最終承認は社内に残します。

サーバー・クラウド・ネットワーク保守

稼働確認、障害切り分け、更新作業、ベンダー連絡など、技術的な継続対応を外部に任せやすい領域です。

バックアップ・運用確認

対象、保存先、世代、復旧方法を整理し、運用状態を定期的に確認します。

ベンダー窓口・見積レビュー

複数ベンダーからの提案や見積を整理し、必要性、優先順位、役割分担を確認します。

台帳・運用資料の整備

システム、契約、アカウント、連絡先などを一覧化し、特定の社員しか分からない状態を減らします。

05 — INTERNAL

社内に残したい判断と責任

外注を利用しても、会社としての最終判断まで外部へ丸投げすることは避けるべきです。特に次の項目は、外部から助言を受けながらも社内責任者が決められる状態にします。

  • 業務・事業の優先順位：どの課題を先に解決するか
  • 予算：何にいくら投資するか
  • アクセス権限：誰にどのデータ・システムを使わせるか
  • リスク受容：どこまで対策し、何を許容するか
  • 社内責任者：外部支援先と連携し、最終判断を行う人を誰にするか

外部パートナーは「責任者をなくす」ためではなく、社内責任者が適切に判断できるよう、情報整理と実行を補うために使うのが基本です。

06 — START

情シス外注を始める前に、まず7項目を棚卸しする

  1. 利用中のシステム・SaaS — 何を、誰が、何の業務で使っているか
  2. 管理者アカウント — 管理者IDと保有者、退職者名義が残っていないか
  3. ベンダー・契約 — 契約先、費用、更新時期、問い合わせ窓口
  4. サーバー・ドメイン・クラウド — 契約主体と管理権限
  5. バックアップ — 対象、保存先、復旧方法
  6. 障害時の連絡先 — 何が起きたら誰へ連絡するか
  7. 現在の困りごと — 問い合わせ、障害、手作業、費用、属人化など

最初から完璧な台帳を作る必要はありません。分からない項目が多いこと自体が、優先して調査すべき場所を示しています。 現状が把握できていない場合は、スポットIT診断のように、棚卸しと課題整理から始める方法もあります。

FAQ

よくあるご質問

IT担当者が一人もいなくても相談できますか？

可能です。専門用語や資料が揃っていることを前提にせず、利用システムや困りごとの確認から整理します。

情シス業務をすべて外注する必要がありますか？

ありません。会社としての優先順位、予算、権限の最終承認などは社内に残し、技術調査や運用実務など必要な範囲だけを外部で補う方法があります。

総務担当者がITを兼任しています。どこから外注すべきですか？

まず、問い合わせ対応、アカウント管理、障害対応、バックアップ、ベンダー対応など、時間がかかっている業務とリスクが高い業務を棚卸しします。そのうえで外部化する範囲を決めます。
